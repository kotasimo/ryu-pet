# りゅうと、ひととき。

実物写真から作った顔と胸のレイヤーを使い、ブラウザでおでこ・頬・顎・耳を撫でられるモデルプレビューです。既存の動画分析ノートも別画面に残しています。スコアやゲーム要素はありません。

## 起動

Node.js 20.19 以上または 22.12 以上を用意します。

```sh
npm install
npm run dev
```

- `/` : モデルプレビュー。開発サーバー起動後の最初の画面です。
- `/analyze` : 以前の動画分析ノート。
- `npm run build` : TypeScript の検査と本番ビルド。非公開写真レイヤーは `dist/` に含まれません。

マウスまたは指で顔の上を押しながら動かします。部位ボタンから反応を試すこともできます。ドラッグ方向・速度・押している時間は反応エンジンに渡されます。

額・頬・顎・耳をドラッグすると、接触点の周辺を三角格子で小さくワープします。写真から切り出した頭・耳・目・頬・口元を一枚の面に重ねてから変形するため、毛色や模様を保ったまま局所的に動きます。接触点から離れるほど変位を弱め、離した後はばねで元に戻します。変形量と復元速度は実測値ではなく仮設定です。

ローカルの実写真レイヤーを読み込んだ Chrome で、額・頬・顎・耳のマウスドラッグと復元を確認しました。接触点の近くで変形し、離れた部分にはほぼ影響しません。画面上の写真とテスト画像は GitHub に含めません。

開発サーバーで `/?debugMesh=1` を開くと、入力イベント、接触部位、メッシュ中心、変位、押し込み量、実際に描画した頂点の最大変位をキャンバス上と `data-mesh-diagnostics` で確認できます。通常画面と本番ビルドには表示されません。マウスイベントの頻度に左右されにくいよう、接触点を追う遅延点からドラッグ方向の変位を計算します。画面上で動いた頭の位置を逆変換して部位を判定します。

実写真を読み込んだ Chrome で、ゆっくりしたドラッグを額・左右の頬・顎・耳に行い、各部位で入力と頂点変位、解放後の復元を確認しました。高DPIの狭い画面でも頬の入力と復元を確認しています。これらは描画と入力の検証であり、実際のりゅうの皮膚の動きを計測した結果ではありません。

頬を撫でる際は、頭全体の移動を抑え、接触点周辺の写真面が一瞬遅れて動きます。頬の中心を少し縮め、周囲を緩やかに戻す変形にし、鼻と目の近くでは変位を減らしています。動いた写真面の座標を逆にたどってマウス位置と当たり判定を合わせます。同じ頬を横にゆっくり撫でるローカル比較では、頭全体の移動が約6pxから約2pxに減り、局所メッシュの最大頂点変位は約12pxから約16pxになりました。素早い往復では変位方向が反転し、解放後は減衰して戻りました。この数値はブラウザテスト条件の画素値で、実物の動きの測定値ではありません。

## 非公開の写真レイヤー

実物写真由来のパーツは `public/private-assets/ryu/model-v1/` に置きます。このフォルダと元写真・動画のフォルダは `.gitignore` で除外され、GitHub には含めません。素材がない環境では、画面に「仮の代替表示」と明記したシルエットが出ます。

開発者が選定済みの正面写真から同じレイヤーを再生成する場合だけ、Pillow を使います。元写真のパスはコマンド引数としてローカルで指定し、スクリプトや設定に書き込まないでください。生成先も非公開フォルダにします。

```sh
python -m pip install pillow
python scripts/prepare-ryu-assets.py --source "<選定済み正面写真のローカルパス>" --output public/private-assets/ryu/model-v1
```

この切り抜き座標は選定済みの **1108×1478 px** の正面寄り写真専用です。ほかの写真にはそのまま使えません。原本は読み取りのみで、生成した透過 PNG と `manifest.json` は別フォルダに保存します。`python scripts/validate-model-assets.py` で11枚の PNG の有無・読み取り・寸法と配置を確認できます。ブラウザ読み込み時も同じ寸法関係を検査し、異常があれば代替表示になります。

Vite の `publicDir` を無効にし、開発サーバーだけがこの11枚と manifest をローカル配信します。`npm run build` で非公開素材は `dist/` にコピーされません。本番ビルドの画面は代替表示です。写真を含むデプロイ方法は別途設計が必要です。

## 動きの根拠と制約

- 頭頂への接触中に頭の高さ・向きが変わる動画、首・顎の周辺に触れている間に顔向きが変わる動画を、**動きの種類の参考**にしました。手で支えられている部分もあり、接触が変化の原因とは確認できていません。
- `src/model/config.ts` の反応量・方向・タイミングはすべて **「仮」** です。頬や耳への接触反応は未観測です。まばたきと呼吸も控えめな仮の周期です。
- `src/model/reaction.ts` は入力とばねの動きを扱い、`ModelCanvas.tsx` は描画を扱います。犬ごとの見た目と反応は設定・非公開素材に分けています。
- 写真1枚の切り抜きから始めたため、顔を大きく回すと2Dの境界や隠れていた面が破綻します。頬・口元のパーツは二重像を避けるため頭に固定しています。閉眼写真を参照した目元の線は、近くの毛の上に描いた仮の表現で、実写真の直接転写ではありません。口の開閉も簡易表現です。
- 局所メッシュは2Dの平面ワープで、実際の皮膚や毛の立体変形を測定したものではありません。大きく引っ張らないよう変位を制限しています。頭部全体の動きも控えめにし、局所変形を見やすくしています。
- 参照した閉眼・開口・横顔の写真と、動画2本の概略時系列は [モデル用の映像・表情観察](docs/model-observations.md) にまとめました。写真は視点・照明が違うため、そのまま正面レイヤーに貼り付けていません。
- 写真・動画の個体確認、正確な接触位置・タイミング、耳単独の動き、接触と反応の因果は未確定です。これらを確認してから反応設定を調整します。

## 次の改善

閉眼・開口・横顔の別写真を位置合わせし、遮蔽部を補修してから差分テクスチャにします。今は位置・照明のずれを避けるため、正面写真由来のレイヤーだけを描画しています。その後、飼い主が見て「りゅうらしい」と感じるかを基準に、見た目と動きの量を調整します。利用者が動画に点を打つ作業は不要です。

## 動画分析ノート

`/analyze` ではローカル動画の再生・シーク・速度変更、特徴点と接触区間の手動記録、表・グラフ表示、バージョン付き JSON の保存と再読み込みができます。動画はアップロードしません。MOV の再生可否はブラウザのコーデック対応によります。コマ送りは約1/30秒のシークで、厳密なフレーム単位ではありません。カメラ移動や視点は座標に影響します。このツールを使わなくてもモデルプレビューは動きます。

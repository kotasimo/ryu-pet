# Issue #4: おでこを撫でる体験の実装と検証

## 目標と現在の体験

静かな正面のポートレートから、おでこに触れると頭の位置・傾きが変わり、実物の横顔写真が見え、正面へ戻る。一連の見た目は写真308と349をローカルで使う。動画3の頭部運動の一部を数値化して再生する。動作を単に画像の局所変形へ置き換えない。既存メッシュは接触感の補助に留める。

## Appearance / Motion Library / Reaction Policy

- **Appearance**: 正面写真308から既存の11レイヤー、横顔写真349から `side_head.png` を生成する。切り抜きは写真ごとの手作業の輪郭で、元写真は変更しない。横顔の視線、鼻、耳、頬の輪郭は別写真そのものに由来する。二枚の撮影条件の違いは残る。
- **Motion Library**: 動画3をOpenCVで5 fpsに間引き、頭部を囲う矩形を基準フレームで一度だけ指定する。Shi–Tomasi特徴点をLucas–Kanadeフローで前後に追跡し、RANSACで基準からの2D部分アフィン変換を推定する。各時刻の正規化平行移動・面内回転・スケール、インライア比に基づく信頼度、欠測を非公開JSONに記録する。顔の向きや感情を自動認識した値ではない。
- **Reaction Policy**: おでこの押下で追跡の有効区間を再生し、横顔写真へ遷移して戻る。3D的な向きと中間姿勢、動作開始時刻、ピクセル倍率、区間のつなぎ方は仮設定。動画では頭頂に手が見えるが、接触が動きの原因とは確定できない。ほかの部位は引き続き仮の反応。

## ローカルで行った抽出

動画3（約16.17秒、720×1280）を81時刻で読み取った。3.6秒を基準にした追跡では34/81時刻で数値を出せた。8秒を基準にした追跡では12/81時刻で数値を出せた。再生には前者の3.4〜4.0秒付近と後者の7.6〜8.8秒付近から、信頼度0.38以上が連続する短い区間のみを選んだ。信頼度不足の値は補間しない。手による遮蔽や横向きへの回転で広い範囲を連続追跡できなかった。

再現用のローカル手順（入力と出力の実パスはGitに保存しない）:

```sh
python -m pip install pillow opencv-python-headless numpy
python scripts/prepare-ryu-assets.py --source "<写真308の絶対パス>" --output public/private-assets/ryu/model-v1
python scripts/prepare-side-view.py --source "<写真349の絶対パス>" --assets public/private-assets/ryu/model-v1
python scripts/extract-head-motion.py --video "<動画3の絶対パス>" --clip-id video-3 --seed-second 3.6 --seed-box 150 310 300 290 --output public/private-assets/ryu/model-v1/motion-video-3.json
python scripts/extract-head-motion.py --video "<動画3の絶対パス>" --clip-id video-3-return --seed-second 8 --seed-box 180 330 300 280 --output public/private-assets/ryu/model-v1/motion-video-3-return.json
python scripts/validate-model-assets.py
npm run dev
```

基準矩形は開発者が動画の実フレームを見て選んだ。アプリ利用者によるアノテーションは不要。追跡データには元ファイルのパス・画像・撮影日時を入れず、非公開フォルダにのみ置く。開発サーバーの許可リストは必要なファイルだけをローカル配信し、`publicDir: false` により本番ビルドへ含めない。

## 映像との比較とブラウザ確認

- 元動画のフレーム列では、約2〜4秒に頭が上がって画面左へ向き、約5〜7秒は横向き、約8〜10秒に正面へ戻る。ブラウザでは正面→左向きの実写真→正面の順序を確認した。時間軸を短縮し、抽出区間間を補っているため、映像とフレーム単位で一致する再生ではない。
- ローカルChromeで私的写真・JSONを読み込み、おでこ押下後約0.85秒の横顔表示、約3.75秒の正面復帰、解放後の静止、JavaScriptエラーなしを確認した。`data-mesh-diagnostics` の `measuredMotion` は真、横顔合成率は約0.88から約0へ変化した。耳→頬→顎→範囲外→額のドラッグと、狭い画面のタッチ入力も別途確認した。
- 実写真プレビューのスクリーンショット、元動画、生成PNG、追跡JSONはGitHubへ含めない。コード、手順、数値の集計だけを共有する。

## 未解決の見た目と測定

横顔切り抜きの首元と正面の胴体に継ぎ目があり、二つの写真で露出と向きが異なる。横向きへの中間フレームは実写真がないためクロスフェードに留まり、3D形状は再現していない。頭部追跡にはカメラ移動と手の影響が混ざる。目・耳の独立した動き、顔の正確なyaw/pitch、接触位置と反応の因果関係は未測定。動画851は目視確認したが、今回の体験の数値再生には使っていない。次は横顔と胴体の接合、色合わせ、より長い追跡区間と顔パーツ別の推定を優先する。
